# MEA Review 产品阶段

当前工作台支持冻结快照、静态规则、Mock 协议、离线重放及本地审阅。发布边界和实际能力见 [README](../README.md)。

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| Phase 0 / M1 | 落地 MIT 许可、Agent 规则和基础 CI，核查现有离线能力 | 182 项测试通过，首个 PR 的 CI 真实跑绿，记录提交与离线证据。文档和配置变更由协调者核对 |
| M2 真实审阅 | 先打通固定 head 的 GitHub PR 只读输入，再验证获准模型的跨文件审阅 | 对 3–5 个真实 PR 保存输入身份、工具调用、成本与候选问题。逐条标注 Real model、Real repo 和人工确认结果，保留真阳性与假阳性原文 |
| M3 ReviewBench | 固定样本与评分协议，对照 Static、Direct LLM 与 Agent | 满足样本准入才出正式分数。报告 Precision、Recall、F1、时延、费用、分母和失败 |
| M4 GitHub 闭环 | 人工确认、行级评论、增量复审与不确定写回对账 | 在自有测试 PR 核对授权、写入结果以及过期锚点处理 |
| M5 发布 | 审阅工作台、可核验案例、README、Demo 和第三方归属 | 许可证与发布决定落实，可从新环境独立体验和复现 |

M3 在正式运行前固定未参与调优的样本、基线、评分规则、样本数、预算和停止条件。不得复用 v3 adjudication 已消费的样本建立新结论。首轮完整评测中，Agent 相对 Direct LLM 的 F1 提升若低于 10 个百分点，冻结负面结果与归因分析，进入 M4/M5。每个产品开发阶段记录 Git SHA、测试命令、退出码、证据、能力类别和独立审查。

## 费用与停止条件

项目所有者已长期授权真实模型调用，每次请求上限 USD 10，本项目累计上限 USD 200。阶段软分配为 M2 USD 30、M3 USD 90、M4 USD 20、预留 USD 60，分配与消耗记入协调账本 `agent-control/SPEND.md`。限额内直接执行并在阶段结果报告实际花费。

单阶段最多修复两轮。第二轮仍未达标时记 PARTIAL，把后续动作写入下一阶段。同一提示词或配置已跑两轮且指标无变化、批次缺少预先声明的样本数或停止条件、仅为边际提升重跑完整评测、阶段分配耗尽时停止。每批调用规模与提供方重试次数均须有界。
